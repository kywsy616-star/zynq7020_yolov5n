> 对应结构文件：`ultralytics/cfg/models/v5/yolov5_crack_speed.yaml`
> 输入分辨率：512 × 384（宽 × 高，即 H=384、W=512）
> 数据集：RDD_China（3 类：crack / alligator crack / pothole）
> 本文所有数字都按该 yaml **实测**给出，可与 yaml 注释直接对照：params 0.721 M、GFLOPs@512×384 = 1.349、GMAC/帧 = 0.674。

## 一、核心计算公式

### 1. 标准卷积层

一次"乘累加"（MAC，Multiply-Accumulate）就是一次乘法加一次加法。卷积层的 MAC 次数为：

```
MAC = 输出高 × 输出宽 × 输出通道 × 输入通道 × 卷积核边长²
```

| 符号 | 含义 | 本模型取值 |
| --- | --- | --- |
| 输出高、输出宽 | 输出特征图的高与宽 | 随层变化（见第三节表） |
| 输入通道 | C_in | 随层变化 |
| 输出通道 | C_out | 随层变化 |
| 卷积核边长 | K（3×3 则 K=3，1×1 则 K=1） | 1 或 3 |

**换算关系**

- 1 次 MAC = 1 次乘法 + 1 次加法
- 1 GMAC = 10⁹ MAC
- 1 GFLOPs ≈ 2 × GMAC（因为 1 次 MAC 算 2 次浮点运算）

**统计口径说明**：偏置、BatchNorm、激活、池化、拼接的运算量都远小于卷积，本文按"纯卷积"统计；
官方 `thop` 口径会把 BN、LeakyReLU、上采样也算进去，两者相差约 2.7%（见第四节）。

### 2. C3 模块（CSP Bottleneck）

结构：输入分两条 1×1 卷积分支 → 主分支经过 n 个 Bottleneck → 与旁路拼接 → 末端 1×1 融合卷积。

```
C3 的 MAC = 首端 1×1 卷积(cv1) + 旁路 1×1 卷积(cv2) + n × 单个 Bottleneck + 末端 1×1 卷积(cv3)

其中单个 Bottleneck 的 MAC = 1×1 卷积的 MAC + 3×3 卷积的 MAC

隐藏通道 c_ = 输出通道 × 0.5(膨胀系数 e)
```

### 3. 输出尺寸公式

```
输出高 = (输入高 + 2 × 填充 − 卷积核边长) ÷ 步长，向下取整后 + 1
```

- 3×3 卷积且步长 2 时，填充 = 1，尺寸恰好减半；
- 1×1 卷积步长 1，尺寸不变；
- 上采样（Upsample ×2）与拼接（Concat）不产生 MAC，但 Concat 会增加通道数，让后面的卷积变贵。

## 二、输入与网络规格

| 项目 | 取值 |
| --- | --- |
| 输入分辨率 | 512 × 384（宽 × 高），3 通道 |
| 类别数 nc | 3（crack / alligator crack / pothole） |
| 检测头类型 | **无锚框（Anchor-Free）**：ultralytics `Detect` + DFL |
| 锚框（anchor） | **不使用**（无 anchor 概念） |
| 回归分支输出 | 每格 4 × reg_max = 4 × 16 = 64 通道 |
| 分类分支输出 | 每格 nc = 3 通道 |
| 每格总输出 | 64 + 3 = **67 通道** |
| 三个尺度输出张量 | 67×48×64（P3/8）、67×24×32（P4/16）、67×12×16（P5/32） |

> ⚠️ **重要纠错**：本模型是 ultralytics 的无锚框头（DFL，reg_max=16），**不是**经典 YOLOv5 的
> "每层 3 个 anchor × (4 + 1 + 3) = 8 通道、共 24 通道"。若按 24 通道估算，检测头会被低估约 100 倍。

### 3. Detect 检测头（层 24）

检测头对 P3 / P4 / P5 三个尺度各建一个分支头，每个尺度含 3 个回归卷积（cv2）+ 3 个分类卷积（cv3）。

| 尺度 | 特征图(H×W) | 输入通道 | 6 个分支卷积的 MAC |
| --- | --- | --- | --- |
| P3/8 | 48 × 64 | 32 | 239.37 M |
| P4/16 | 24 × 32 | 64 | 81.08 M |
| P5/32 | 12 × 16 | 128 | 30.89 M |
| **6 个分支卷积小计** | | | **351.33 M** |
| DFL 投影卷积(16→1) | 4 × 4032 | 16 | 0.26 M |
| **小计** | | | **351.59 M** |

> 检测头占全模型 **53.6%** 的算力——**一个检测头就吃掉了全模型一半以上的算力**，
> 这是本模型最大的算力来源，也是最值得优化的地方。

### 4. 手算示例（可直接用计算器复核）

**示例 1：层 0 卷积（3×3/2，3 → 16 通道）**

```
输出尺寸：384 ÷ 2 = 192，512 ÷ 2 = 256
MAC = 192 × 256 × 16 × 3 × 3 × 3 = 21,233,664 ≈ 21.23 M
```

**C3 结构图（以层 6 为例）**

层 6 的 C3 内部流程：对半分 → 一路精加工 → 拼回来 → 融合。

**① 整体结构（数据怎么流）**

```
                input x : 48 x 24 x 32
                |
   +------------+------------+
   |                         |
   v                         v
   cv1: Conv 1x1 (48->24)    cv2: Conv 1x1 (48->24)
   |  24x24x32               |  24x24x32
   v                         |
   Bottleneck 1              |
   |  24x24x32               |
   v                         |
   Bottleneck 2              |
   |  24x24x32               |
   +------------+------------+
                v
                Concat : 24 + 24 = 48 x 24 x 32
                |
                cv3 : Conv 1x1 (48->48)
                |
                v
                output y : 48 x 24 x 32
```

主分支 cv1 把 48 张压成 24 张（隐藏通道），再过 2 个 Bottleneck 精加工；旁路 cv2 也压成 24 张但保持原样。两条路拼接 24 + 24 = 48，最后由 cv3 融合输出 48 张。

**② Bottleneck 内部结构**

```
    input x : 24 x 24 x 32
    |
    +-------------+
    |             |
    v             |
    cv1: Conv 1x1 |
        24 -> 24  |
    v             |
    cv2: Conv 3x3 |
        24 -> 24  |
    v             |
    +-------------+
    v
    (+) add   <-- residual (shortcut)
    |
    v
    output : 24 x 24 x 32
```

每个 Bottleneck：1×1 降维 → 3×3 卷积 → 与原始输入残差相加；通道始终 24、尺寸 24×32 不变。

**示例 2：层 6 C3(n=2，48 → 48 通道)，输入 48×24×32**

```
隐藏通道 c_ = 48 × 0.5 = 24；特征图面积 = 24 × 32 = 768

cv1      : 768 × 24 × 48 × 1 =   884,736
cv2      : 768 × 24 × 48 × 1 =   884,736
Bottleneck ×2：
    单个 1×1 : 768 × 24 × 24 × 1 =   442,368
    单个 3×3 : 768 × 24 × 24 × 9 = 3,981,312
    两个合计 : (442,368 + 3,981,312) × 2 = 8,847,360
cv3      : 768 × 48 × 48 × 1 = 1,769,472

合计 = 884,736 + 884,736 + 8,847,360 + 1,769,472 = 12,386,304 ≈ 12.39 M
```

**SPPF 结构图与算法（层 9）**

层 9 的 SPPF(96 → 96, k=3)：先用 1×1 卷积把 96 通道压到 48，再做 3 次级联的 3×3 最大池化（每次结果都保留），把 4 份特征拼接成 192 通道，最后 1×1 融合回 96 通道。

**① 结构（数据怎么流）**

```
                  input x : 96 x 12 x 16
                  |
                  cv1 : Conv 1x1  (96 -> 48)
                  |
                  v
                  y0 (48x12x16)-------------------+
                  |                               |
                  MaxPool (k=3, s=1, p=1)         |
                  |                               |
                  v                               |
                  y1 (48x12x16)-----------------+ |
                  |                             | |
                  MaxPool (k=3, s=1, p=1)       | |
                  |                             | |
                  v                             | |
                  y2 (48x12x16)---------------+ | |
                  |                           | | |
                  MaxPool (k=3, s=1, p=1)     | | |
                  |                           | | |
                  v                           | | |
                  y3 (48x12x16)-------------+ | | |
                  |                         | | | |
                  v                         v v v v
                  Concat : [y0, y1, y2, y3] = 4 x 48 = 192 x 12 x 16
                  |
                  cv2 : Conv 1x1  (192 -> 96)
                  |
                  v
                  output y : 96 x 12 x 16
```

链式 3 次 3×3 最大池化：等效感受野依次为 3×3、5×5、7×7；MaxPool 只做比较，算力记 0。

**② 算法与算力**

```
y0 = cv1(x)                          # Conv 1x1: 96 -> 48
y1 = MaxPool(y0)                     # MaxPool k=3, s=1, p=1（尺寸不变）
y2 = MaxPool(y1)
y3 = MaxPool(y2)
out = cv2( Concat(y0, y1, y2, y3) )  # Conv 1x1: 4x48 = 192 -> 96

算力（输入 96 x 12 x 16，HxW = 12 x 16 = 192）
  cv1 : 192 x 48 x 96  x 1 =   884,736
  Pool: 0（只比较、不乘加）
  cv2 : 192 x 96 x 192 x 1 = 3,538,944
  合计 = 4,423,680 ≈ 4.42 M MAC（占全模型 0.7%）

参数量 = (48x96 + 96) + (96x192 + 192) = 4,704 + 18,624 = 23,328
```

SPPF 全层只占 4.42 M MAC（全模型 0.7%），是“低成本换大感受野”的模块。

**示例 3：层 24 检测头 P3 尺度，输入 32×48×64**

```
特征图面积 = 48 × 64 = 3072

回归分支 cv2：
    Conv 32→64, 3×3 : 3072 × 64 × 32 × 9 =  56,623,104
    Conv 64→64, 3×3 : 3072 × 64 × 64 × 9 = 113,246,208
    Conv 64→64, 1×1 : 3072 × 64 × 64 × 1 =  12,582,912
分类分支 cv3：
    Conv 32→32, 3×3 : 3072 × 32 × 32 × 9 =  28,311,552
    Conv 32→32, 3×3 : 3072 × 32 × 32 × 9 =  28,311,552
    Conv 32→ 3, 1×1 : 3072 ×  3 × 32 × 1 =     294,912

P3 小计 = 239,370,240 ≈ 239.37 M
（同法算得 P4 ≈ 81.08 M，P5 ≈ 30.89 M）
```

### 2. 换算到官方口径

```
纯卷积合计                       = 656.04 M ≈ 0.656 GMAC
+ BatchNorm、激活、上采样（约 18.3 M）
────────────────────────────────────────────────
官方 thop 口径（含辅助算子）      = 674.3 M = 0.674 GMAC/帧
对应 GFLOPs = 2 × 0.674          = 1.349
```

### 3. 与 yaml 注释对照（三项全部一致）

| 指标 | 本文实测 | yaml 注释 | 是否一致 |
| --- | --- | --- | --- |
| 参数量 | 720,681 = 0.721 M | 0.721 M | ✔ |

### 4. 关于"0.308 GMAC"的纠错

如果只统计 Backbone 与 Neck、把检测头当成几 M 的小模块，会得到约 **0.308 GMAC**，
比真实值 **0.674 GMAC** 少了一半以上。差异几乎全部来自**被漏算的检测头（351.59 M）**，
而不是"C3 内部通道拆分"或"SPPF 统计口径"——本模型的 C3 / SPPF 数值本身就与官方口径吻合。

## 五、硬件算力与帧率对应

### 1. 理论纯计算极限

Zynq-7020 PL 端按「100 MHz 主频、并行度 32 MAC/cycle」计算：

```
峰值算力     = 100 MHz × 32 = 3.2 GMAC/s
理想推理时间 = 0.674 GMAC ÷ 3.2 GMAC/s ≈ 0.211 s ≈ 210 ms/帧
```

### 2. 工程实际区间

考虑 DDR 访存、tile 分片、总线仲裁等开销：

- 调优良好（大 tile + 长 burst）：**60 ~ 100 ms/帧**
- 普通分片：**120 ~ 220 ms/帧**
- 碎片化访存（当前 2.45 s 现象）：DDR 等待占比 > 90%，算力利用率 < 15%

### 3. 25 FPS 目标要求

```
所需有效算力 = 0.674 GMAC/帧 × 25 帧/秒 ≈ 16.9 GMAC/s
```

16.9 GMAC/s 远超 7020 单 PL 核心峰值 3.2 GMAC/s，必须靠**流水线并行、多 batch 分摊**；否则需要下调分辨率或降低帧率。

### 4. 另一组参考假设（yaml 注释口径）

yaml 注释按「220 个 DSP48E1、200 MHz」估算，得到完全不同的峰值：

| 假设口径 | 主频 | 并行度 | 峰值算力 | 能否满足 25 FPS（需 16.9 GMAC/s） |
| --- | --- | --- | --- | --- |
| 本文（保守） | 100 MHz | 32 MAC/cycle | 3.2 GMAC/s | 峰值不够，需多核/降分辨率 |
| yaml 注释（乐观） | 200 MHz | 220 个 DSP | 44 GMAC/s | 峰值够，但需利用率 ≥ 38% |

> 两套口径的差别只在**主频与并行度假设**，模型本身的 0.674 GMAC/帧 是同一份实测值。
> 做方案对比时请注明采用哪一套。

## 六、结论（一句话版）

- 单帧 **纯卷积 0.656 GMAC**，官方口径 **0.674 GMAC/帧 = 1.349 GFLOPs**（与 yaml 完全一致）；
- 三段占比：骨干 33.6% / 颈部 12.8% / **检测头 53.6%（最大头）**；
- 25 FPS 需要有效算力 **≥ 16.9 GMAC/s**；本档 P3 骨干已由 48 收窄到 32，是"帧率优先"的取舍点。
