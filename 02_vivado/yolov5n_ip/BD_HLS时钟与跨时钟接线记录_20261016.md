# HLS时钟与跨时钟BD接线记录

日期：2026-10-16。工具：Vivado 2020.2。器件：xc7z020clg400-2。

## 1. 本次目标与完成范围

在现有R6.4 / 10版HLS IP上测试提高运行频率的接线方案：

- HLS、ILA及64位测量计数器使用150 MHz。
- PS GP/HP接口、原AXI互连和视频模块原100 MHz逻辑域保持100 MHz。
- HDMI像素时钟及5倍串行时钟保持原连接，并非将所有视频时钟统一改成100 MHz。
- 补齐150 MHz复位，以及控制、数据两条AXI通路的跨时钟转换。
- 已执行并通过`validate_bd_design`，BD已保存。

本次终点是BD接线与Validate通过。
没有修改HLS C/C++、Vitis源码、模型、权重和寄存器接口。
没有运行综合、布局布线、bitstream生成、XSA导出或FPGA下载。
因此，150 MHz实际时序、资源、功能及FPS仍待用户后续构建和上板验证。

工程：`yolov5n_ip.xpr`。
设计：`yolov5n_ip.srcs/sources_1/bd/zynq/zynq.bd`。
本次快照、Tcl与核对文件位于[记录目录][clock-dir]。

## 2. 为什么使用Clocking Wizard，而不是直接使用FCLK1

操作前，用户已在PS配置中将FCLK1的请求频率填写为150 MHz。
但Vivado实际计算结果为：

```text
FCLK1请求值：150 MHz
FCLK1实际值：142.857132 MHz
当前IO PLL分频：7 × 1
```

请求值不一定能由当前PS PLL的整数分频精确实现。
为保留CPU、DDR及其他PS外设配置，本次没有调整PS PLL。
改为从原FCLK0的100 MHz输入，通过独立MMCM生成准确的150 MHz。
原有FCLK1配置保留，但该输出未接入本次HLS时钟网络。

```text
processing_system7_0/FCLK_CLK0，100 MHz
    ├─ 原100 MHz逻辑域
    └─ clk_wiz_hls_150/clk_in1
           └─ clk_out1，150 MHz
                ├─ yolov5n_top_10/ap_clk
                ├─ ila_3/clk
                ├─ c_counter_binary_3/CLK
                ├─ proc_sys_reset_0/slowest_sync_clk
                └─ 两个AXI转换器各自的150 MHz侧
```

Validate后的端口频率信息确认上述150 MHz端口均为`150000000 Hz`。
此处是BD配置及频率传播结果，不是已经在板上测量的时钟。

## 3. 新增与复用的模块

| 模块名 | 类型 | 用途 |
|---|---|---|
| `clk_wiz_hls_150` | Clocking Wizard 6.0 | 原100 MHz输入，生成HLS专用150 MHz |
| `axi_cc_hls_ctrl` | AXI Clock Converter 2.1 | AXI-Lite控制通路100→150 MHz |
| `axi_cc_hls_mem` | AXI Clock Converter 2.1 | AXI4数据通路150→100 MHz |
| `hls_reset_zero` | xlconstant 1.1 | 1位常量0，停用辅助/调试复位 |
| `proc_sys_reset_0` | Processor System Reset 5.0 | 复用用户已添加的模块，生成150 MHz域复位 |

原`rst_ps7_0_100M`继续服务原100 MHz域。
原`axi_smc_acc`仍运行100 MHz，未启用其多时钟模式。
采用两个显式转换器，使原互连端口及复位连接可以保持原状。

## 4. Clocking Wizard配置与接线

| 配置项 | 当前值 |
|---|---|
| Primary input frequency | 100.000 MHz |
| Primary source | No buffer；PS FCLK已经经过时钟缓冲 |
| CLKOUT1 requested frequency | 150.000 MHz |
| CLKOUT1 phase / duty | 0度 / 50% |
| 输出缓冲 | BUFG |
| Reset | 启用，低有效`resetn` |
| Locked | 启用 |

| 引脚 | 实际连接 |
|---|---|
| `clk_in1` | `processing_system7_0/FCLK_CLK0` |
| `resetn` | `processing_system7_0/FCLK_RESET0_N` |
| `locked` | `proc_sys_reset_0/dcm_locked` |
| `clk_out1` | HLS、ILA、计数器、150 MHz复位时钟及转换器150 MHz侧 |

工具当前选择的MMCM参数为：

```text
输入分频D = 2
反馈倍频M = 19.875
输出分频O = 6.625
输出 = 100 MHz ÷ 2 × 19.875 ÷ 6.625 = 150 MHz
```

后续改频率应修改请求输出频率，让工具重新计算MMCM参数。
不需要手工照抄或固定上述M/D/O。

## 5. 150 MHz复位配置与连接

复位不是一个以150 MHz翻转的信号；它的释放同步到150 MHz时钟。
原PS低有效复位同时送给两个域的复位模块，由各域分别同步释放。

| `proc_sys_reset_0`输入 | 当前极性/作用 | 实际连接 |
|---|---|---|
| `slowest_sync_clk` | 复位同步时钟 | `clk_wiz_hls_150/clk_out1` |
| `ext_reset_in` | 低有效 | `processing_system7_0/FCLK_RESET0_N` |
| `dcm_locked` | 1表示时钟锁定 | `clk_wiz_hls_150/locked` |
| `aux_reset_in` | 高有效 | `hls_reset_zero/dout`，常量0 |
| `mb_debug_sys_rst` | 高有效 | 同一常量0 |

当前`C_EXT_RESET_HIGH=0`、`C_AUX_RESET_HIGH=1`，已读取实际传播结果确认。
Vivado 2020.2中外部复位极性随连接源传播，`C_EXT_RESET_HIGH`为只读项。
不要只凭端口名称猜极性，也不要把低有效辅助复位长期接0。

`peripheral_aresetn`连接：

```text
yolov5n_top_10/ap_rst_n
axi_cc_hls_ctrl/m_axi_aresetn
axi_cc_hls_mem/s_axi_aresetn
```

该复位模块其余输出目前不用，保持悬空。
ILA没有外部复位端口；现有计数器也未启用额外复位端口。

## 6. AXI控制通路：100→150 MHz

```text
PS M_AXI_GP0，100 MHz
  → ps7_0_axi_periph/M05_AXI，100 MHz
  → axi_cc_hls_ctrl/S_AXI
  → 跨时钟转换
  → axi_cc_hls_ctrl/M_AXI
  → yolov5n_top_10/s_axi_control，150 MHz
```

| 转换器端口 | 实际连接 |
|---|---|
| `S_AXI` | `ps7_0_axi_periph/M05_AXI` |
| `M_AXI` | `yolov5n_top_10/s_axi_control` |
| `s_axi_aclk` | 原FCLK0，100 MHz |
| `m_axi_aclk` | Clocking Wizard输出，150 MHz |
| `s_axi_aresetn` | `rst_ps7_0_100M/peripheral_aresetn` |
| `m_axi_aresetn` | `proc_sys_reset_0/peripheral_aresetn` |

协议为AXI4-Lite，数据32位，转换器局部寄存器地址宽7位，使用异步模式、3级同步。
7位来自HLS控制接口的实际寄存器偏移宽度，不代表PS系统地址只有7位。
HLS寄存器基地址保持`0x40000000`，地址范围仍为64 KiB。
原互连的`M05_ACLK/M05_ARESETN`保持100 MHz域连接。

## 7. AXI数据通路：150→100 MHz

```text
yolov5n_top_10/m_axi_gmem，150 MHz
  → axi_cc_hls_mem/S_AXI
  → 跨时钟转换
  → axi_cc_hls_mem/M_AXI
  → axi_smc_acc/S00_AXI，100 MHz
  → processing_system7_0/S_AXI_HP1，100 MHz
  → DDR控制器
```

| 转换器端口 | 实际连接 |
|---|---|
| `S_AXI` | `yolov5n_top_10/m_axi_gmem` |
| `M_AXI` | `axi_smc_acc/S00_AXI` |
| `s_axi_aclk` | Clocking Wizard输出，150 MHz |
| `m_axi_aclk` | 原FCLK0，100 MHz |
| `s_axi_aresetn` | `proc_sys_reset_0/peripheral_aresetn` |
| `m_axi_aresetn` | `rst_ps7_0_100M/peripheral_aresetn` |

协议为AXI4，数据32位、地址64位，使用异步转换模式，3级同步。
这是现有HLS主接口传播得到的宽度，没有把gmem改成64位数据总线。
HLS可访问DDR地址段仍为`0x00000000～0x3FFFFFFF`。

两个转换器在Vivado 2020.2中的配置名为`CONFIG.ACLK_ASYNC=1`。
150:100为3:2，不能当成普通整数倍率转换使用。
属性中保留的`ACLK_RATIO=1:2`在异步模式下不表示本次实际时钟比；以两侧频率为准。
即使两个时钟同源，也保留异步转换；不要因此给HLS内部路径添加false path。

## 8. 以后在Vivado中如何修改HLS运行频率

1. 打开本工程的`zynq` Block Design。
2. 双击`clk_wiz_hls_150`，不要去修改PS的FCLK0或闲置FCLK1。
3. 在Clocking Options确认输入仍为100 MHz、No buffer。
4. 在Output Clocks修改`clk_out1`的Requested Frequency。
   例如125.000、150.000 MHz；同时检查工具给出的实际输出频率。
5. 保持输出端连接不变。HLS、ILA、计数器和150 MHz侧复位会跟随同一输出。
   实例名里的`150`只是名称，改成125 MHz后不强制要求重命名。
6. 检查两个AXI转换器仍为异步模式，两侧时钟和复位分别对应各自域。
7. 点击Validate Design并保存BD，确认没有频率、接口或复位域错误。

也可以在Vivado原生Tcl Console修改，例如：

```tcl
set_property CONFIG.CLKOUT1_REQUESTED_OUT_FREQ {125.000} \
    [get_bd_cells clk_wiz_hls_150]
validate_bd_design
save_bd_design
```

修改请求值后，应以Validate传播的实际频率为准。
只修改端口的`FREQ_HZ`元数据或XDC约束，不会替代真实时钟源配置。
本次没有修改HLS综合时钟；原RTL仍是按100 MHz目标生成的版本。
若后续150 MHz布线时序无法满足，再另建HLS solution，以6.667 ns目标重新调度。
不能为了让报告通过而放宽实际时钟约束或屏蔽HLS内部时序路径。

用户后续构建时，需要重新生成BD输出产物，并运行综合、实现和bitstream。
确认新bit与XSA匹配，再更新Vitis平台及所用的FSBL/PS初始化文件。
本次PS FCLK0仍为100 MHz，但平台交接仍应使用本次新硬件的配套文件。

## 9. ILA和性能测量的变化

ILA的三个探针信号保持原定义：event16位、valid1位、自由运行计数器64位。
只将ILA与计数器的时钟一起迁移到HLS专用时钟，避免直接采样跨域事件。

```text
150 MHz：1周期 = 6.6667 ns
耗时ms = 计数器差值 / 150000

125 MHz：耗时ms = 计数器差值 / 125000
100 MHz：耗时ms = 计数器差值 / 100000
```

旧100 MHz分析脚本不能直接用于新150 MHz采样，否则时间会被算成实际的1.5倍。
后续分析时必须记录实际时钟频率；本次不改历史R6.4采样文件及其100 MHz计算脚本。
CPU串口若使用PS全局定时器，其换算依据不是HLS时钟，不要直接乘除1.5。

## 11. 快照与复现说明

记录目录中主要文件：

- `before_zynq.bd`、`before_yolov5n_ip.xpr`：操作前文件快照。
- `before_zynq.tcl`：从打开的设计导出的操作前BD Tcl。
- `apply_hls_150mhz_bd.tcl`：本次接线步骤；带新模块存在性检查，不能在完成后重复执行。
- `validate_hls_150mhz_bd.tcl`：仅验证现有设计并导出实际属性，不运行构建。
- `after_zynq.tcl`：完成后BD Tcl。
- `after_properties.txt`：实际端口、频率、复位与地址属性。
- `validate_design.log`：最终验证命令返回状态。
- `validate_console_excerpt.log`：最终验证的原生Vivado输出，包含上述两项提示。
- `verify_clock_bd.js`、`connection_audit.json`：离线核对连接、地址和未改动范围。

开始操作时，用户已添加一个尚未接线的`proc_sys_reset_0`。
因此操作前快照是当时的编辑状态，不应当作已经通过Validate的100 MHz完整基线。
若只需回退运行频率，可将Clocking Wizard输出改成100 MHz并重新构建；
这种回退仍保留转换器，不等同于恢复原来完全直连的100 MHz拓扑。
